## What this assessment tests

Attack-path reasoning over AD as a graph (M06), credential recovery without an exploit (M10), and
identity-based lateral movement (M11). Success is *reaching* domain compromise from an unprivileged
account **and** documenting each hop as a reproducible finding with root cause and remediation.

## Intended path(s)

The forest is provisioned with **several independent edges** so the shortest path can vary; a strong
student finds at least one full path and ideally more than one. All start from `lab\r.olsen`
(Domain Users only).

### Primary intended path — Kerberoast → ACL → DCSync

1. **Enumerate as `r.olsen`.** Collect the domain with a BloodHound-style collector (SharpHound /
   `bloodhound-python -u r.olsen -p Lab-Passw0rd! -d lab.local -c All`). Any authenticated user can
   read most of the directory. Look for: SPN-bearing accounts, `DONT_REQ_PREAUTH` accounts, and
   outbound control edges from `r.olsen`.
2. **Kerberoast `svc_sql`.** `svc_sql` has a registered SPN (MSSQL). Request its service ticket
   (`GetUserSPNs.py lab.local/r.olsen:Lab-Passw0rd! -request`, or Rubeus `kerberoast`). The account's
   password is set to a crackable value in provisioning — crack offline with Hashcat mode `13100`
   and a small wordlist. **Why the domain hands it over:** any authenticated principal can request a
   service ticket for any SPN; its encryption is derived from the service account's password hash, so
   a weak password is crackable entirely offline and invisible to the DC.
3. **Use `svc_sql`'s ACL edge.** `svc_sql` (directly, or via a nested group such as `SQL Admins`)
   holds **`WriteDacl`/`GenericAll`** over a privileged object — in the shipped design, over the
   `Domain Admins` group *or* over an account that is a DA. Verify the edge live
   (`Get-ObjectAcl` / PowerView, or read it in BloodHound) before acting.
4. **Escalate to a domain-compromise primitive.** Two acceptable finishes:
   - Grant `svc_sql` (or `r.olsen`) **DCSync** rights by writing a DACL that adds
     `DS-Replication-Get-Changes` / `-All` on the domain head, then `secretsdump.py`/`Mimikatz
     lsadump::dcsync` the `krbtgt` and `Administrator` hashes. **This is domain compromise** even
     without Domain Admins membership — replication of secrets = full credential access.
   - Or add the controlled principal to `Domain Admins` via the `WriteDacl`/`GenericAll` edge, then
     authenticate to DC01 and read the flag.
5. **Prove it.** Read the DA-only flag (`\\DC01\C$\Users\Administrator\Desktop\flag.txt` or the
   provisioned marker location) and demonstrate the domain-wide primitive (DCSync of `krbtgt`).

### Alternate paths (any one is a pass)

- **AS-REP roast → reuse.** A provisioned account has Kerberos pre-auth disabled
  (`DONT_REQ_PREAUTH`); `GetNPUsers.py` yields an AS-REP hash, crack offline (Hashcat `18200`). If
  that account has an onward edge or its password is reused for a privileged/local-admin context,
  chain from there.
- **ACL-only chain (no cracking).** `r.olsen` is inside a group with `GenericAll`/`AddMember` over an
  intermediate group (e.g. `Helpdesk` → `Server Admins`); self-add, then that group's rights over a
  higher principal, ending at a DA-controlling edge. Purely permission-driven.
- **Delegation abuse.** A host/account configured for **unconstrained** or **constrained** delegation
  (or **RBCD** writable by a controlled principal) → S4U / ticket abuse to authenticate as a
  privileged user to the DC.
- **Credential reuse to SRV01.** `svc_sql` is local admin on SRV01; dump LSASS/SAM there for a
  cached DA or a reused local-admin secret, then move to DC01.

## Expected flags / evidence

- **DA-only flag:** `LAB-FLAG-{uuid}` from the Administrator desktop / provisioned DA-only location.
- **Domain-wide primitive:** DCSync output showing the `krbtgt` (and Administrator) hash — the
  strongest single proof of domain compromise.
- Per-hop evidence: the Kerberoast/AS-REP hash and successful offline crack; the ACL edge read live;
  the DACL modification (before/after); and the authenticated action on DC01. Deterministic filenames
  per 16.1.

## Common wrong turns

- **Trusting BloodHound blindly.** Acting on a stale/incorrect edge without verifying it against the
  live directory — mark down; step 1 of the rubric's methodology band requires manual verification.
- **Online password spraying / brute force** against the domain — noisy, lockout-inducing, and
  usually unnecessary; the intended paths are offline-crack or pure-ACL.
- **Jumping straight for the DC** with no path (e.g. attempting a public exploit against DC01)
  instead of walking the graph — the forest is patched; the compromise is by misconfiguration.
- **"I'm Domain Admin" with only a shell screenshot** — no finding, no root cause, no reproduction.
  Not a pass.
- **Destructive actions** — resetting a password they can't restore, deleting objects, disabling the
  DC. Fail on safety; also breaks determinism for the next student (reset from snapshot).
- **Stopping at `svc_sql`** and calling it domain compromise — a service account is a *hop*, not the
  objective, unless it directly yields the domain-wide primitive.

## Grading key

Map to the student rubric bands. Suggested weighting (100):

- **Domain compromise reached & proven (35):** DA-only flag + DCSync/DA primitive, from `r.olsen`,
  every hop justified by a *verified* misconfiguration.
- **Findings quality (25):** each abused misconfig rubric-complete and reproducible; CVSS rationale
  reflects what was demonstrated (e.g. Kerberoast of a weak service account → High/Critical
  depending on onward reach).
- **Methodology (15):** enumerate→verify→exploit; collector output verified by hand; explicit,
  correct attack-path graph; no destructive/out-of-scope actions; isolation confirmed.
- **Impact & remediation (15):** business-terms impact; per-hop root cause and fix — *managed service
  accounts / strong passwords* (Kerberoast), *ACL/tiering hygiene* (WriteDacl), *remove/limit
  delegation*, *protect DCSync rights* — each with a detection note (event IDs / DS replication
  monitoring).
- **Distinction (+10):** ≥2 independent full paths, or shortest + quieter alternative, with
  detection trade-off reasoning and pattern-level remediation (tiered admin model, protected users,
  gMSAs, ACL review).

**Fail conditions:** path not reached; reached by undocumented guessing; no marker evidence;
destructive or out-of-scope actions; isolation not verified.

## Model check-yourself answers (abbreviated)

1. Verify (a) the ACL edge still exists on the live object and (b) `svc_backup`'s DA membership is
   effective (not shadowed/denied) — collectors go stale; acting on a phantom edge burns detection
   budget and proves nothing.
2. The DC issues a service ticket for any SPN to any authenticated user, encrypted with the service
   account's password-derived key → offline crack; feasible because the account had a weak,
   human-set password. Fix: gMSA / long random password + `AES` only + SPN hygiene.
3. Replicating directory secrets yields every credential in the domain (incl. `krbtgt` → Golden
   Tickets); membership is irrelevant — the *right* is the compromise.
4. RoE/detection goals decide: a detection-aware engagement favours the quieter path and records
   both the fastest and the stealthiest, with expected telemetry, for the blue team.
5. Missing: what/where (the specific misconfig and object), reproduction, evidence with the marker,
   business impact, severity rationale, and remediation — i.e. it is not yet a finding.
