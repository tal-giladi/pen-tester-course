# Instructor / solutions — Assessment 3 (Windows privilege escalation)

> Instructor material. Not linked from `_sidebar.md`. Have students complete the assessment before
> reading. All work targets the isolated `lab-05-win-privesc` VM (host-only, no-egress), from the
> synthetic `lab\lowpriv` logon, against the benign `C:\flag.txt` (admin-only). Never a real
> machine.

## What this assesses

M05 as an unscaffolded engagement: from a `lab\lowpriv` interactive logon, enumerate the Windows
privesc surface, pick and *justify* one path to SYSTEM/local-admin, exploit and verify it, and
write a report-ready finding with mechanism, remediation, and detection. Mirrors the 05.3 exercise
but gives only the logon and the objective.

## The lab's planted vectors (per the lab README — independent paths)

- A **service with a weak/misconfigured ACL** (e.g. `SERVICE_CHANGE_CONFIG` for `lowpriv`).
- An **unquoted service path** with a writable directory segment.
- **`AlwaysInstallElevated`** set in both HKLM and HKCU.
- An **autorun / DLL-hijack** opportunity (and, per the M05 solution, a scheduled task and a token
  privilege such as `SeImpersonate` may be present).

Any is valid; grade *mechanism + verification + remediation + detection*, not the choice.

## Intended "best" path and the four deliverables

The most reliable, tool-light path is the **weak service DACL** — deterministic, immediate, no wait
and no launch dependency. Model submission (using `UpdaterSvc`-style service as the example):

**1. Enumeration → candidate set.**
- `whoami /priv` and `whoami /groups` — establish current integrity (an admin's filtered token runs
  **Medium**; membership ≠ current access) and note any `SeImpersonate`.
- Service ACLs with an access-check tool (`accesschk -uwcqv lowpriv *` / PowerUp) → the service
  granting `SERVICE_CHANGE_CONFIG`.
- `sc qc <svc>` for unquoted `binPath` with spaces → then `icacls`/`Get-Acl` on each earlier
  segment (writable prefix?).
- `reg query` **both** `HKLM\SOFTWARE\Policies\Microsoft\Windows\Installer` and the HKCU equivalent
  for `AlwaysInstallElevated`.
- Scheduled tasks + writability of their actions; DLL-hijack candidates (Procmon `NAME NOT FOUND`
  in a writable dir).

**2. Mechanism (graded core).** Weak DACL: privileged actor = the SCM launching the service as
`LocalSystem`; controlled input = the `binPath` value, which `SERVICE_CHANGE_CONFIG` lets `lowpriv`
rewrite; primitive = arbitrary command execution as SYSTEM when the service (re)starts. This is
**CWE-732** (DACL wrongly grants config to a non-admin), not a Windows bug. Student must explain
why the privilege transfers (SCM runs `binPath` under the configured account).

**3. Reproduction + verification.**
- `accesschk -uwcqv lowpriv <svc>` (shows `SERVICE_CHANGE_CONFIG`) → **record the original binPath**
  → `sc config <svc> binPath= "cmd /c net localgroup administrators lab\lowpriv /add"` →
  `sc stop <svc> & sc start <svc>` → open a **new** session → `whoami /groups` shows
  `BUILTIN\Administrators` → elevate → `type C:\flag.txt` = `LAB-FLAG-{uuid}`. (Variant: point
  binPath at a benign SYSTEM proof and read the flag directly as SYSTEM.)
- Verification = `whoami` / `whoami /groups` / `whoami /priv` + the flag. "Got SYSTEM" without it is
  not proven.

**4. Remediation + detection.**
- Fix: restrict the service DACL to administrators (remove `SERVICE_CHANGE_CONFIG` from
  `lowpriv`/broad groups); run the service least-privilege.
- Detect: **Event ID 7040** (service start-type/config change), process creation of `sc.exe config`,
  a SYSTEM service child of `cmd`/`net.exe`. ATT&CK **T1543.003**.
- **Cleanup:** restore original `binPath` (`sc config <svc> binPath= "<original>"`); remove
  `lowpriv` from Administrators if that variant was used; restore the `clean` snapshot.

## Acceptable alternative paths (grade mechanism + verification + fix + detection)

- **Unquoted service path** — *only if* they prove a writable earlier segment and plant the
  earlier-resolving `.exe` (CWE-428, T1574.009). Reject if they call it exploitable under default
  `C:\`/`Program Files` ACLs with no writable prefix shown.
- **`AlwaysInstallElevated`** MSI as SYSTEM — must show **both** hives = 1 (CWE-250, T1548);
  msiexec-as-SYSTEM is loud, note it.
- **Writable scheduled-task action** (T1053.005).
- **`SeImpersonate` potato** — accept an explained mechanism with the four steps and the
  `whoami /priv` precondition; do **not** require a weaponized PoC at this level.
- **DLL hijack** — only with the failed load shown (Procmon `NAME NOT FOUND`) and a writable
  searched directory.

## Common wrong turns

- Confusing group membership with current integrity (not accounting for UAC's split token /
  Medium-integrity filtered token).
- Claiming an unquoted path is exploitable without proving a writable prefix.
- Setting `AlwaysInstallElevated` in one hive and expecting it to work (needs both).
- "I got SYSTEM" with no `whoami`/flag evidence.
- Missing remediation **or** detection; no cleanup/original-config note.
- Hand-repairing the VM instead of restoring the snapshot.

## Expected evidence / markers

A shell/session as `NT AUTHORITY\SYSTEM` or local admin, shown via `whoami` / `whoami /groups` /
`whoami /priv`, and `type C:\flag.txt` = `LAB-FLAG-{uuid}`.

## Grading key (100 pts)

| Dimension | Pts | Award full when… | Deduct when… |
|---|---|---|---|
| Method | 20 | enumerated services/tasks/installer/token-privs; candidate set; justified pick; integrity vs membership understood | one-shot WinPEAS; no candidate set; conflates membership with access |
| Evidence | 15 | `whoami`/`/priv`/`/groups` + flag captured; reproducible | assertion with no output |
| Exploitation &amp; mechanism | 25 | privileged actor + controlled input + privilege transfer correct and explicit; writable-prefix/config-right *proven* | assumed prefix; command with no "why" |
| Impact | 15 | SYSTEM = full local compromise + lateral-movement enabler, business terms | "it's bad" |
| Remediation &amp; detection | 15 | specific ACL/least-priv fix **and** event-ID + ATT&CK detection | one missing; hand-wave |
| Reporting | 10 | template filled; CVSS justified; cleanup/original config noted | missing fields; no cleanup |

CVSS for local SYSTEM: e.g. `CVSS:3.1/AV:L/AC:L/PR:L/UI:N/S:U/C:H/I:H/A:H` ≈ 7.8 (High). Accept a
defended score; PR:L reflects the required foothold.
