# A7 — Full penetration test · instructor material & grading key

> Instructor material. Not linked from `_sidebar.md`. Do not distribute to students. Targets are the
> shipped `lab-07-web` (+`lab-08` surface), `lab-04-linux-privesc`, and `lab-11-lateral`
> environments; reconcile object/credential names against those labs' READMEs and provisioning if
> they change. This is a *reporting* assessment as much as an exploitation one — grade the report
> hardest.

## What this assessment tests

The whole workflow end to end plus **professional reporting** (M16): recon/enumeration (M02/M03),
web/API exploitation (M07/M08), Linux local privesc (M04), credential recovery & reuse / lateral
movement (M10/M11), and — decisively — a complete, two-altitude report with a coherent attack
narrative.

## Intended chain (external → crown jewel)

The environments expose **multiple** footholds and privesc vectors, so the exact chain varies. A
strong submission connects them into one story. Reference chain:

1. **Enumerate the web surface** (`http://web:5000`) — WSTG-style. Present: SQLi + reflected XSS at
   `/search?q=`, IDOR/BOLA at `/api/orders/<id>`, weak-JWT/`alg:none` at `/login`, BFLA at
   `/api/admin/users`, stored XSS at `/profile`, SSRF at `/fetch?url=`, OS command injection at
   `/ping?host=`, path traversal at `/download?file=`, SSTI at `/render?name=`, unrestricted upload
   at `/upload`. (T1595/T1190 recon→exploit.)
2. **Obtain a foothold.** Fastest: **OS command injection** at `/ping?host=` → command execution as
   the app user (T1190 → T1059). Alternatives that also qualify: **SSTI** at `/render` → RCE;
   **unrestricted upload** at `/upload` → webshell; or **SQLi** at `/search` to dump the `users`
   table + hashes (T1190), crack a hash offline (T1110.002), and reuse it (T1078) for an interactive
   login. Any of these is an acceptable foothold if evidenced and reproducible.
3. **Escalate on the host.** The foothold host carries **several independent** local-privesc vectors
   (SUID exec primitive, `sudo` NOPASSWD on an interactive program, world-writable root cron, a
   capability on a copied interpreter, and a PATH-abusable SUID helper — see `lab-04` README). Any
   one → **root** (T1548 / T1068). Read `/root/flag.txt` (`LAB-FLAG-{uuid}`).
4. **Move laterally.** On the rooted host, hunt credential material (a "deploy key" / service-account
   secret in a home dir, config, or backup — the `lab-11` reuse mechanic, T1552/T1078) that
   authenticates to the **second host** (the crown jewel). Reach `host-b` and read its flag
   (`LAB-FLAG-{uuid}`) — the "customer data" asset (T1021.004 SSH / T1550-style reuse).
5. **Stop and write.** Build the timeline from the action log; write both altitudes.

**Crown-jewel proof:** the `host-b` flag, framed as the customer-data reach the CISO asked about.

## Expected findings (minimum)

| ID | Finding (example) | Sev | Key ATT&CK |
|---|---|---|---|
| F-1 | Foothold vuln (e.g. OS command injection `/ping?host=`) | Critical/High | T1190, T1059 |
| F-2 | Credential exposure/recovery enabling access (SQLi dump + crack, or key found) | High | T1110.002 / T1552 |
| F-3 | Linux local privilege escalation (the vector used) | High | T1548 / T1068 |
| F-4 | Credential reuse / lateral movement to host-b | High | T1078 / T1021.004 |
| F-5+ | Other confirmed surface (IDOR/BOLA, SSRF, weak JWT, etc.) reported honestly | Med/… | T1190 |

Additional web/API issues not on the critical path should be **reported but not over-weighted** — a
strong student presents them in the table and details, ranked below the chain.

## Common wrong turns

- **Bug list instead of a chain.** Ten findings, no narrative connecting foothold → root → host-b —
  misses the point of A7; the chain is the deliverable.
- **Jargon-laden executive summary** (SQLi/CVSS/PtH) — automatic markdown on the two-altitude band;
  16.3 forbids it.
- **Unreproducible findings** — "I exploited the search box" with no exact request/payload.
- **No action log → invented timeline** — timeline inconsistent with evidence timestamps.
- **Destructive testing** — dropping tables via the SQLi, lockout brute force on `/login` — RoE
  violation; deduct and note.
- **Over-collection** — dumping and pasting entire tables of "customer data" instead of minimal
  evidence with the marker.
- **Stopping at root on host-a** and never reaching the crown jewel, yet claiming customer-data
  impact — impact must be demonstrated, or explicitly scoped as "reachable, not shown" with reason.

## Model report excerpts (for calibration)

**Executive-summary paragraph (target quality):**
> *"Starting from the public website with no login, we were able to run our own commands on the
> server that hosts it, take full control of that server, and from there reach a second internal
> system holding customer records. In practical terms, an attacker on the internet could obtain
> Harbor & Vine's customer data without any inside help. The individual weaknesses are
> well-understood and fixable; the most urgent can be closed this week. Overall the environment's
> security is below what we would expect for a system holding customer data, driven mainly by a
> single unsafe way of handling user input and by reused credentials — themes we detail with
> concrete fixes."*

**Narrative paragraph (target quality):**
> *"From the internet and unauthenticated, we exploited command injection in the site's diagnostics
> feature (F-1, T1190/T1059) to run commands as the web user, then escalated to root through a
> permissive `sudo` rule (F-3, T1548.003). On the host we recovered an SSH deploy key (F-2, T1552)
> that a shared service account reused on a second internal host, which we reached over SSH (F-4,
> T1021.004) and where the customer-records marker was readable. A single input-handling flaw thus
> chained to full compromise of two hosts and their data in under an hour."*

**Timeline (target):** `14:03 F-1 confirmed · 14:11 shell as web · 14:20 root (F-3) · 14:29 deploy
key found (F-2) · 14:34 host-b via SSH (F-4) · 14:36 crown-jewel marker read.`

## Grading key

Suggested weighting (100):

- **Chain completed & evidenced (25):** external → foothold → root → host-b crown jewel, marker at
  each stage.
- **Findings (20):** rubric-complete, reproducible, correct CVSS v3.1+v4.0 with rationale.
- **Two-altitude writing (20):** genuinely non-technical exec summary; engineer-actionable findings;
  same facts both places.
- **Narrative & timeline (15):** coherent, attacker-ordered, ATT&CK-mapped, timeline consistent with
  evidence.
- **Remediation roadmap (10):** risk-prioritised, effort-aware, ≥1 strategic/pattern-level fix
  (input-handling standard + SAST; credential/key hygiene).
- **Professionalism & safety (10):** isolation verified; minimal data handling; deterministic
  evidence; confidentiality classification; honest limitations; nothing destructive/out of scope.

**Distinction:** report would survive a real debrief — honest posture, defensible severities, class-
level remediation, day-one Critical escalated in-engagement and recorded.

**Fail:** chain incomplete/undocumented; report missing required sections; jargon exec summary;
non-reproducible findings; no marker evidence; safety boundary breached.

   impact — neither buried (they're real) nor inflated (they're not on the critical path).

   *detected* it — value independent of the findings.

   narrative and roadmap. Don't sum CVSS; explain the escalation.

   the escalation path, and recorded in the action log and the Scope/RoE §"contacts & escalation".
